# Текст для дипломной работы в научно-техническом стиле

## Введение

Актуальность темы определяется необходимостью сокращения ручных операций при заключении и исполнении договоров купли-продажи земельных участков. Оформление таких сделок связано с вводом сведений об участке, проверкой данных сторон, подготовкой договорной документации, загрузкой файлов, подписанием документов и контролем этапов исполнения. При раздельном хранении этих данных возрастает вероятность ошибок в реквизитах, нарушения последовательности действий и потери сведений о состоянии сделки.

Информационная система автоматизации договоров купли-продажи земли предназначена для объединения указанных операций в едином программном комплексе. Система хранит сведения о пользователях, земельных участках, договорах, документах, подписях и задачах. За счет централизованного хранения данных обеспечивается связь между карточкой участка, договором, сопроводительными документами и действиями пользователей.

Объектом исследования является процесс заключения и исполнения договоров купли-продажи земельных участков. В рамках данного процесса рассматриваются операции подготовки договора, проверки сведений об участке, фиксации сторон сделки, загрузки документов, подписания договора и контроля выполнения связанных задач.

Предметом исследования являются программные средства автоматизации указанного процесса. В работе рассматривается проектирование и реализация веб-приложения, которое обеспечивает хранение данных, обработку запросов через API, разграничение доступа, работу с документами и отображение состояния договоров в пользовательском интерфейсе.

Цель дипломной работы состоит в разработке информационной системы для автоматизации процесса заключения и исполнения договоров купли-продажи земли. Для достижения цели выполняется анализ предметной области, формируются требования к системе, проектируется архитектура приложения, разрабатывается структура базы данных, реализуется серверная и клиентская часть, проводится проверка работы основных сценариев.

В качестве методов исследования используются анализ предметной области, моделирование бизнес-процессов, проектирование базы данных, объектно-ориентированное проектирование, разработка веб-приложения и функциональное тестирование. Серверная часть реализуется на Python с использованием Django REST Framework. Клиентская часть реализуется на React и TypeScript. Для хранения данных используется PostgreSQL с расширением PostGIS. Развертывание выполняется с использованием Docker Compose.

## Анализ предметной области

Процесс купли-продажи земельного участка включает подготовку сведений об объекте, определение сторон договора, согласование условий, оформление документов, подписание и контроль исполнения обязательств. В ручном режиме сведения об участке, договоре и документах могут храниться в разных источниках. Это усложняет проверку данных и затрудняет контроль состояния сделки.

Автоматизация данного процесса предполагает создание системы, в которой сведения об участке, договоре и документах связаны между собой. Пользователь создает карточку земельного участка, указывает кадастровый номер, адрес, площадь, категорию земель, назначение и тип собственности. После этого создается договор, в котором фиксируются продавец, покупатель, участок, цена, сроки, условия оплаты и особые условия. При дальнейшем сопровождении сделки к договору добавляются документы, создаются задачи и фиксируется подписание.

Участниками процесса являются пользователи с различными правами доступа. В системе предусмотрены роли клиента, риелтора, юриста, нотариуса, администратора компании и системного администратора. Ролевая модель используется для ограничения операций с договорами, участками, документами и подписями. Действия пользователей фиксируются в журнале активности, что позволяет восстановить последовательность операций.

## Выбор технологического стека

Серверная часть системы разработана на Python с использованием Django и Django REST Framework. Django применяется для описания моделей данных, выполнения миграций, работы с пользователями и обработки запросов. Django REST Framework используется для создания API, сериализации данных и проверки входных параметров.

Для хранения данных используется PostgreSQL. Расширение PostGIS применяется для работы с геометрическими данными земельных участков. База данных хранит сведения о пользователях, ролях, договорах, участках, документах, подписях, этапах исполнения, задачах и действиях пользователей.

Клиентская часть реализована на React и TypeScript. Интерфейс построен как рабочее пространство, в котором пользователь переходит между разделами договоров, участков, документов и отчетов. Для взаимодействия с сервером используется слой API-запросов. При отсутствии соединения с сервером данные могут храниться в локальном хранилище браузера, что позволяет продолжить работу в демонстрационном режиме.

Развертывание системы выполняется через Docker Compose. В состав среды входят контейнеры базы данных PostgreSQL/PostGIS, Redis, серверного приложения Django, клиентского приложения React и Nginx. Redis используется для кэширования и фоновой обработки задач. Nginx выполняет функции веб-сервера и обратного прокси.

## Требования к информационной системе

Информационная система должна обеспечивать регистрацию пользователей, вход в систему, выход из системы и получение профиля пользователя. Авторизация выполняется с использованием JWT-токенов. Права доступа определяются ролью пользователя.

Система должна обеспечивать ведение земельных участков. Для участка хранятся кадастровый номер, регион, район, населенный пункт, адрес, площадь, категория земель, назначение, тип собственности, признак проверки и примечание. Для участка также могут храниться документы, сведения о собственниках, обременениях и оценке стоимости.

Система должна обеспечивать создание и редактирование договоров купли-продажи земли. Договор содержит название, описание, продавца, покупателя, земельный участок, цену, валюту, дополнительные сборы, даты действия, статус, условия оплаты и особые условия. Статус договора отражает его положение в процессе оформления и исполнения.

Система должна обеспечивать загрузку документов к договору и земельному участку. Для документа сохраняются название, тип, имя файла, размер, дата загрузки и состояние проверки. При загрузке выполняется проверка типа и размера файла.

Система должна обеспечивать электронное подписание договора. При подписании сохраняются подписант, тип подписи, данные сертификата, данные подписи, IP-адрес, сведения о браузере и признак действительности подписи. После подписания статус договора изменяется в соответствии с логикой обработки.

Система должна обеспечивать постановку задач по договорам. Для задачи указываются название, договор, срок выполнения, ответственный, приоритет и состояние выполнения. Задачи используются для контроля действий, связанных с подготовкой и исполнением договора.

Система должна обеспечивать формирование отчетной информации. В отчетном разделе отображаются сведения о количестве договоров, земельных участков, открытых задач, документов на проверке, общей сумме договоров и готовности договоров. Пользователь может выгрузить отчет в формате CSV.

## Проектирование информационной системы

Архитектура системы построена по клиент-серверной схеме. Клиентская часть отвечает за отображение данных и ввод сведений пользователем. Серверная часть принимает запросы, выполняет проверку данных, применяет бизнес-логику и обращается к базе данных. База данных хранит состояние системы и обеспечивает целостность связей между сущностями.

Клиентская часть обращается к серверу через REST API. Запросы передаются по HTTP. При наличии токена доступа он добавляется в заголовок запроса. Сервер проверяет права пользователя, выполняет операцию и возвращает ответ в формате JSON. Полученные данные приводятся клиентской частью к структуре рабочего пространства.

Основными компонентами серверной части являются модуль пользователей, модуль земельных участков и модуль договоров. Модуль пользователей хранит учетные записи, профили, роли, сессии и журнал активности. Модуль земельных участков хранит кадастровые сведения, территориальную привязку, документы, обременения и оценки. Модуль договоров хранит сведения о договорах, документах, подписях, этапах, шаблонах, комментариях и задачах.

Пользовательский интерфейс включает боковую навигацию и рабочую область. В системе предусмотрены разделы обзора, договоров, участков, документов и отчетов. В верхней части интерфейса размещены элементы поиска, синхронизации, импорта участка, загрузки документа, создания договора и авторизации.

## Проектирование базы данных

База данных отражает структуру предметной области и обеспечивает хранение сведений, необходимых для сопровождения земельных сделок. Центральной сущностью является договор. Договор связан с продавцом, покупателем и земельным участком. С договором связаны документы, подписи, этапы исполнения, комментарии и задачи.

Сущность пользователя используется для хранения учетных данных, контактной информации, сведений о компании и данных электронной подписи. Роли пользователей хранятся отдельно и позволяют назначать одному пользователю несколько правовых и организационных функций. Журнал активности фиксирует операции пользователя и содержит сведения об объекте действия, времени выполнения, IP-адресе и описании операции.

Сущность земельного участка хранит кадастровый номер, территориальные сведения, адрес, площадь, категорию, назначение, геометрию, тип собственности и признак проверки. Для участка предусмотрены связанные сущности собственников, документов, обременений и оценок. Такая структура позволяет хранить как основные характеристики участка, так и сведения, влияющие на возможность заключения сделки.

Сущность договора хранит условия сделки и состояние ее прохождения. Для договора сохраняются цена, валюта, дополнительные сборы, даты, условия оплаты и особые условия. Этапы договора применяются для контроля выполнения действий по сделке. Документы договора хранят файлы и сведения о проверке. Подписи фиксируют факт подписания и сведения о подписанте.

Структура базы данных нормализована. Повторяющиеся сведения вынесены в отдельные таблицы и связываются внешними ключами. Это уменьшает дублирование данных и обеспечивает согласованность при изменении сведений о пользователе, участке или договоре.

## Реализация серверной части

Серверная часть реализована на Django REST Framework. Для договоров используется набор моделей, представлений и сериализаторов. Модель договора хранит сведения о сторонах, земельном участке, цене, сроках и статусе. Модели документов, подписей, этапов, шаблонов, комментариев и задач связаны с договором через внешние ключи.

API договоров реализует операции создания, просмотра, редактирования, удаления, подписания, получения истории, генерации документа и получения статистики. При создании и изменении договора сериализатор проверяет наличие продавца, покупателя, участка и корректность дат. При подписании создается запись подписи и при необходимости изменяется статус договора.

Модуль земельных участков реализует хранение справочников регионов, районов, населенных пунктов, категорий земель и назначений. Для участка поддерживаются операции поиска, фильтрации, создания, изменения и удаления. В запросах используются связи с территориальными и справочными таблицами, а также фильтры по кадастровому номеру, адресу, площади и признаку проверки.

Модуль пользователей расширяет стандартную модель Django. В модели пользователя хранятся email, телефон, ФИО, сведения о компании, признаки верификации и сведения об электронной подписи. Дополнительные модели профиля, ролей, сессий и журнала активности применяются для разграничения доступа и контроля действий.

## Реализация клиентской части

Клиентская часть реализована на React и TypeScript. Основной компонент приложения управляет выбранным разделом, поисковой строкой, выбранным договором и модальными окнами. Для создания и редактирования данных используются формы договора, участка, документа и авторизации.

Рабочий стол системы отображает показатели по текущим данным. Пользователь видит количество договоров, активных договоров, открытых задач, сумму договоров, непроверенные участки и документы на проверке. На этой же странице размещаются последние договоры, задачи, участки и документы.

Раздел договоров отображает карточки договоров и панель сведений по выбранному договору. В карточке отображаются номер, название, статус, сумма и участок. В панели сведений отображаются продавец, покупатель, кадастровый номер, адрес, площадь, сумма, срок действия и связанные документы. Из этого раздела пользователь может открыть редактирование, подписать договор или загрузить документ.

Раздел участков отображает таблицу земельных участков. В таблице указаны кадастровый номер, регион, площадь, назначение и статус проверки. Пользователь может добавить участок через форму импорта и изменить признак проверки.

Раздел документов отображает загруженные файлы, их тип, размер, дату загрузки, связанный договор и статус проверки. Пользователь может загрузить документ и перевести его в состояние принятого.

Раздел отчетов формирует сводку по договорам, участкам, задачам и документам. В этом разделе рассчитываются общий объем договоров, средняя готовность, количество проверенных участков и количество принятых документов. Отчет может быть сохранен в формате CSV.

## Взаимодействие компонентов

Взаимодействие компонентов выполняется по схеме React-клиент, REST API, Django ORM и PostgreSQL. Пользователь выполняет действие в интерфейсе. Клиентская часть формирует запрос и передает его на сервер. Серверная часть проверяет данные, выполняет операцию через модели Django и возвращает результат клиенту.

При создании договора форма передает название, стороны, участок, сумму, сроки и условия. Клиент преобразует эти данные в структуру запроса. Сервер принимает запрос, выполняет проверку через сериализатор, создает запись договора и возвращает созданный объект. Клиент обновляет состояние рабочего пространства и отображает договор в списке.

При загрузке документа клиент формирует запрос с использованием `FormData`. Сервер проверяет файл, сохраняет его в файловом хранилище и создает запись документа. После этого документ становится доступен в разделе документов и в карточке договора.

При подписании договора клиент вызывает метод API для выбранного договора. Сервер создает запись подписи, определяет тип подписанта и сохраняет сведения о подписи. Если договор находится в состоянии ожидания подписи, его статус переводится в состояние подписанного.

При синхронизации клиент запрашивает участки, договоры и задачи. Для договоров дополнительно загружаются детальные сведения, включая документы. Ответы сервера приводятся к единой структуре, которая используется всеми разделами интерфейса.

## Тестирование

Тестирование системы выполнялось функциональным методом. Проверялись сценарии авторизации, создания договора, редактирования договора, изменения статуса, подписания, добавления участка, подтверждения проверки участка, загрузки документа, принятия документа, создания задачи, выполнения задачи, поиска и формирования отчета.

При проверке авторизации система принимает учетные данные, сохраняет токен доступа и отображает профиль пользователя. При создании договора система проверяет обязательные поля и не выполняет сохранение при отсутствии названия, продавца, покупателя, участка или суммы. При корректном заполнении договор добавляется в список и отображается в разделе договоров.

При проверке работы с участками система создает запись участка с кадастровым номером, адресом, регионом, площадью, категорией, назначением и типом собственности. После подтверждения проверки участок получает соответствующий статус и может использоваться при создании договора.

При проверке документов система загружает файл, сохраняет сведения о нем и связывает документ с договором или участком. После принятия документа его статус изменяется. При проверке подписания договор переводится в состояние подписанного, а сведения о подписи сохраняются в базе данных.

При проверке отчетности система рассчитывает показатели по текущим данным и формирует CSV-файл. Поиск проверяется по номеру договора, названию, сторонам сделки, кадастровому номеру, адресу, документам и задачам. При отсутствии соединения с API система переходит в локальный режим и использует данные браузера.

## Заключение

В ходе выполнения дипломной работы разработана информационная система автоматизации процесса заключения и исполнения договоров купли-продажи земли. Система охватывает операции учета пользователей, ведения земельных участков, создания договоров, загрузки документов, подписания, постановки задач и формирования отчетности.

В результате работы спроектирована архитектура клиент-серверного веб-приложения. Серверная часть реализована на Django REST Framework. Клиентская часть реализована на React и TypeScript. Для хранения данных используется PostgreSQL/PostGIS. Для развертывания применяется Docker Compose с контейнерами серверного приложения, клиентского приложения, базы данных, Redis и Nginx.

Разработанная структура базы данных обеспечивает хранение связанных сведений о пользователях, ролях, договорах, участках, документах, подписях, этапах исполнения, задачах и действиях пользователей. Использование внешних ключей и ограничений целостности позволяет поддерживать согласованность данных при изменении состояния сделки.

Практический результат работы заключается в создании системы, которая сокращает ручной ввод данных, объединяет сведения о сделке в одном интерфейсе и позволяет отслеживать состояние договора на этапах оформления и исполнения. Система может использоваться как основа для дальнейшей разработки программного решения в области сопровождения земельных сделок.

## Техническое задание

Информационная система предназначена для автоматизации процесса заключения и исполнения договоров купли-продажи земли. Система обеспечивает хранение сведений о пользователях, земельных участках, договорах, документах, подписях, задачах и отчетах.

Цель создания системы состоит в снижении объема ручных операций при подготовке и сопровождении земельных сделок. Система должна обеспечить создание договора на основе сведений об участке и сторонах сделки, загрузку документов, подписание договора, контроль задач и получение отчетной информации.

Система разрабатывается как веб-приложение с разделением клиентской и серверной части. Серверная часть реализуется на Python с использованием Django REST Framework. Клиентская часть реализуется на React и TypeScript. Для хранения данных используется PostgreSQL с расширением PostGIS. Для кэширования и фоновых задач используется Redis. Развертывание выполняется с применением Docker Compose, Gunicorn и Nginx.

Система должна поддерживать регистрацию и авторизацию пользователей. Система должна хранить роли пользователей и применять их при проверке доступа к операциям. Система должна обеспечивать создание, изменение, просмотр и удаление договоров. Система должна обеспечивать создание и проверку земельных участков. Система должна обеспечивать загрузку и проверку документов. Система должна обеспечивать создание электронной подписи договора. Система должна обеспечивать ведение задач и формирование отчетов.

База данных должна хранить сведения в нормализованной структуре. Договор должен быть связан с продавцом, покупателем и земельным участком. Документы, подписи, этапы, комментарии и задачи должны быть связаны с договором. Земельный участок должен быть связан со справочниками региона, района, населенного пункта, категории и назначения земли.

Пользовательский интерфейс должен обеспечивать доступ к разделам обзора, договоров, участков, документов и отчетов. В интерфейсе должны быть предусмотрены поиск, синхронизация с API, создание договора, импорт участка, загрузка документа, вход и выход из системы.

Приемка системы выполняется по результатам функционального тестирования. Система считается работоспособной, если пользователь может войти в систему, создать участок, создать договор, загрузить документ, подписать договор, создать задачу, изменить состояние задачи, выполнить поиск и сформировать отчет.
